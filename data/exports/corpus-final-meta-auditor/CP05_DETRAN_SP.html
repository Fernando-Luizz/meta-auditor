Itens do relatório Lighthouse para revisão manual. Quando o texto coincide com padrões frequentes em inglês, é exibida uma versão em português; caso contrário mantém-se o original para cruzamento com a ferramenta.

  • Custom controls have associated labels Controles interativos personalizados devem ter rótulos associados via aria-label ou aria-labelledby para que leitores de tela anunciem seu propósito.
  • Custom controls have ARIA roles Controles interativos personalizados devem ter role ARIA adequado (ex.: role="button", role="checkbox") para que tecnologias assistivas compreendam sua função.
  • User focus is not accidentally trapped in a region Verifique manualmente: o usuário deve conseguir entrar e sair de qualquer controle ou região com Tab/Shift+Tab sem que o foco fique preso.
  • Interactive controls are keyboard focusable Controles interativos personalizados devem ser acessíveis por teclado (Tab para focar, Enter/Espaço para ativar) e exibir indicador de foco visível.
  • Interactive elements indicate their purpose and state Elementos interativos devem indicar claramente seu estado (ativo, desativado, expandido, selecionado) e ser distinguíveis de elementos estáticos visualmente e via ARIA.
  • The page has a logical tab order A ordem de foco pelo teclado (Tab) deve seguir a ordem visual da página. Verifique pressionando Tab em todos os elementos interativos: o foco deve percorrer o conteúdo de forma previsível.

  • Offscreen content is hidden from assistive technology Conteúdo fora da viewport deve estar oculto para tecnologias assistivas via display:none ou aria-hidden="true". Caso contrário, é lido pelo leitor de tela mesmo invisível.
  • HTML5 landmark elements are used to improve navigation Use elementos HTML5 de marco semântico (<main>, <nav>, <header>, <footer>, <aside>) para melhorar a navegação por tecnologias assistivas.
