Camada determinística executiva

Impacto

Esta barreira bloqueia a identificação correta do controle. Quem depende de leitor de tela ou navegação assistida não consegue entender com clareza o que o elemento faz, o que impede ou compromete a execução da tarefa.

Leitores de tela

Como corrigir
Há links na página sem nenhum texto. O leitor de tela ou anuncia a URL crua ou pula sem dizer nada: em ambos os casos, impossível saber para onde o link vai. O time de produto precisa colocar um texto descritivo em cada um, indicando claramente o destino.

Camada assistida por IA

Por que priorizar
Usuários que dependem de leitores de tela não conseguem identificar para onde os links levam, pois não há texto descritivo associado a eles. Essa barreira impede completamente a navegação e o acesso às funcionalidades, tornando a correção urgente.
Quem é afetado
Imagine tentar usar um elevador onde os botões não têm números ou rótulos. Você aperta um botão, mas não sabe se vai subir, descer ou para qual andar. Para quem usa leitor de tela, os links sem texto funcionam assim: o programa anuncia apenas a URL ou nada diz, deixando impossível saber o que cada link faz.
O que precisa mudar
Cada link precisa ter um texto claro e descritivo que indique seu destino ou função. O usuário deve conseguir entender para onde vai ou o que acontece ao clicar, sem precisar adivinhar ou tentar.
Ação da gestão
Encaminhar para o time web como prioridade alta e solicitar revisão de todos os links sem texto descritivo.

Camada determinística executiva

Impacto

Esta barreira torna o componente semanticamente incoerente para tecnologias assistivas. O elemento existe visualmente, mas pode ser anunciado de forma errada, incompleta ou contraditória, prejudicando entendimento e operação.

Usuários cegos utilizam leitores de tela como NVDA, JAWS ou VoiceOver. Quando um elemento não tem nome ou descrição, ele simplesmente não existe para esse usuário: o software passa direto sem anunciar nada.

Como corrigir
Há atributos ARIA apontando para identificadores ausentes, inválidos ou desconectados do elemento correto. Com isso, o leitor de tela procura nomes ou descrições que não encontra, e o componente fica incoerente. O time deve revisar referências de rótulo e descrição, garantindo que cada identificador exista, seja único e esteja ligado ao elemento certo.

Camada assistida por IA

Por que priorizar
Usuários cegos que dependem de leitores de tela não conseguem acessar a função de busca porque os rótulos e descrições dos elementos estão quebrados ou apontam para referências inexistentes. Essa barreira impede completamente o uso de uma funcionalidade crítica do site, tornando a correção urgente.
Quem é afetado
Imagine tentar seguir instruções de alguém que aponta para um local, mas a descrição não corresponde ao que existe de verdade. Usuários cegos enfrentam isso quando um leitor de tela tenta ler um rótulo que não existe ou aponta para o lugar errado, deixando-os sem saber o que fazer no campo de busca.
O que precisa mudar
Os elementos de busca indicados precisam ter seus rótulos e descrições corrigidos para que o leitor de tela consiga identificar corretamente o que cada campo faz. Isso significa revisar as referências que conectam os rótulos aos campos de entrada e garantir que todas apontam para elementos válidos.
Ação da gestão
Encaminhar para o time web e solicitar correção dos rótulos e descrições dos elementos de busca indicados.

Camada determinística executiva

Impacto

Esta barreira reduz a clareza da interface e aumenta a chance de erro durante a navegação. O usuário encontra o controle, mas não recebe informação suficiente para agir com confiança.

Leitores de tela

Como corrigir
Há botões na página sem texto ou rótulo. Para quem usa leitor de tela, esses botões não existem: o software não anuncia a função do controle e o usuário não sabe se deve clicar. O time de produto precisa dar a cada botão um nome acessível que diga claramente o que ele faz, usando texto visível, aria-label ou aria-labelledby.

Camada assistida por IA

Por que priorizar
Usuários que dependem de leitores de tela não conseguem identificar a função do botão de login porque ele não possui um nome acessível. Essa barreira impede o acesso a uma funcionalidade crítica da página e afeta diretamente a capacidade de navegação independente.
Quem é afetado
Para quem usa leitor de tela, é como encontrar um botão em uma porta sem nenhuma indicação do que ele faz. O software não consegue anunciar a função do controle, deixando o usuário sem saber se deve clicar ou qual é o propósito daquele elemento. Sem essa informação, a pessoa fica impossibilitada de usar a funcionalidade.
O que precisa mudar
O botão de login precisa receber um nome acessível que descreva claramente sua função. Isso pode ser feito adicionando texto visível no botão, um rótulo associado ou uma descrição que o leitor de tela consiga anunciar quando o usuário navega até ele.
Ação da gestão
Encaminhar para o time web e solicitar revisão de botões sem nome acessível na página de login.

Camada determinística executiva

Impacto

Prejudica a experiência sem necessariamente bloquear o acesso. Vale incluir na próxima rodada de melhorias.

Usuários com limitação motora dependem de alvos clicáveis adequados, espaçamento entre controles e navegação previsível para evitar toques acidentais e retrabalho.

Como corrigir
Vários botões e links do site têm área de clique menor do que o mínimo para uso em celular. Quem tem tremor ou dedo largo acaba ativando o elemento errado. O time de produto precisa aumentar essas áreas: não é mudança visual grande, mas faz diferença real para quem usa o site em mobilidade ou com dificuldade motora.

Camada assistida por IA

Por que priorizar
Usuários com limitações motoras não conseguem clicar ou tocar com precisão em alvos muito pequenos ou muito próximos uns dos outros. Essa barreira afeta a navegação básica do site e deve ser corrigida no próximo ciclo de desenvolvimento.
Quem é afetado
Imagine tentar apertar um botão de elevador muito pequeno ou muito perto de outro botão enquanto o elevador está em movimento. Usuários com tremor nas mãos, artrite ou quem usa o site em movimento enfrentam a mesma dificuldade ao tentar clicar em links ou botões muito compactos.
O que precisa mudar
Os links indicados precisam ter uma área de toque maior ou estar mais espaçados entre si, para que qualquer pessoa consiga ativá-los com facilidade, mesmo com controle motor limitado. Isso inclui aumentar o tamanho do elemento ou adicionar espaçamento interno e externo.
Ação da gestão
Encaminhar para o time de produto e solicitar aumento das áreas de toque e clique nos elementos indicados.

A3 · Checklist Manual Recomendado (10)

Itens do relatório Lighthouse para revisão manual. Quando o texto coincide com padrões frequentes em inglês, é exibida uma versão em português; caso contrário mantém-se o original para cruzamento com a ferramenta.

  • Custom controls have associated labels Controles interativos personalizados devem ter rótulos associados via aria-label ou aria-labelledby para que leitores de tela anunciem seu propósito.
  • Custom controls have ARIA roles Controles interativos personalizados devem ter role ARIA adequado (ex.: role="button", role="checkbox") para que tecnologias assistivas compreendam sua função.
  • User focus is not accidentally trapped in a region Verifique manualmente: o usuário deve conseguir entrar e sair de qualquer controle ou região com Tab/Shift+Tab sem que o foco fique preso.
  • Interactive controls are keyboard focusable Controles interativos personalizados devem ser acessíveis por teclado (Tab para focar, Enter/Espaço para ativar) e exibir indicador de foco visível.
  • Interactive elements indicate their purpose and state Elementos interativos devem indicar claramente seu estado (ativo, desativado, expandido, selecionado) e ser distinguíveis de elementos estáticos visualmente e via ARIA.
  • The page has a logical tab order A ordem de foco pelo teclado (Tab) deve seguir a ordem visual da página. Verifique pressionando Tab em todos os elementos interativos: o foco deve percorrer o conteúdo de forma previsível.
  • The user's focus is directed to new content added to the page Quando conteúdo novo é adicionado à página (diálogo, notificação, painel), o foco deve ser direcionado automaticamente para ele e retornar ao elemento de origem ao ser fechado.
  • Offscreen content is hidden from assistive technology Conteúdo fora da viewport deve estar oculto para tecnologias assistivas via display:none ou aria-hidden="true". Caso contrário, é lido pelo leitor de tela mesmo invisível.
  • HTML5 landmark elements are used to improve navigation Use elementos HTML5 de marco semântico (<main>, <nav>, <header>, <footer>, <aside>) para melhorar a navegação por tecnologias assistivas.
  • Visual order on the page follows DOM order A ordem visual deve corresponder à ordem do DOM. Se CSS reordena visualmente elementos, verifique se a sequência de leitura do leitor de tela ainda faz sentido.
