Camada determinística executiva

Impacto

Os links indicados pela ferramenta apresentam contraste insuficiente entre texto e fundo, conforme indicado pela auditoria automática. Pessoas com baixa visão têm dificuldade para localizar caminhos importantes no portal.

Usuários com baixa visão dependem de contraste adequado, zoom e tipografia legível. Quando o texto e o fundo têm pouca diferença visual, títulos e parágrafos podem ficar difíceis ou impossíveis de ler, mesmo com ampliação.

Como corrigir
Revisar as combinações de cor dos links indicados pela ferramenta, ajustando a cor do texto e/ou do fundo. Validar a razão de contraste mínima exigida pela WCAG: 4.5:1 para texto normal e 3:1 para texto grande.

Camada assistida por IA

Por que priorizar
Usuários com baixa visão não conseguem ler os textos indicados pela ferramenta porque a diferença entre a cor do texto e o fundo é insuficiente. Por ser um problema que afeta a legibilidade básica do conteúdo, a correção deve ser tratada com urgência.
Quem é afetado
Imagine tentar ler um documento impresso com tinta muito clara sobre papel branco, mesmo sob boa iluminação. Usuários com baixa visão enfrentam dificuldade semelhante ao acessar textos com contraste insuficiente no site, pois a diferença entre as cores não oferece clareza suficiente para leitura confortável.
O que precisa mudar
As combinações de cor nos pontos indicados precisam ser ajustadas para garantir contraste adequado entre o texto e o fundo. O objetivo é que qualquer pessoa consiga ler os textos com clareza, mesmo com visão reduzida ou em condições de iluminação variável.
Ação da gestão
Encaminhar para o time de design e solicitar revisão das cores dos textos indicados.

Camada determinística executiva

Impacto

Esta barreira reduz a clareza da interface e aumenta a chance de erro durante a navegação. O usuário encontra o controle, mas não recebe informação suficiente para agir com confiança.

Usuários que acionam interfaces por voz dependem de nomes visíveis e acessíveis coerentes, para que o comando falado corresponda ao elemento exibido na tela.

Como corrigir
O nome acessível deve conter o texto visível do link, preferencialmente no início, para que usuários de controle por voz consigam acionar o elemento pelo texto que enxergam na tela. Quando o rótulo visível e o nome interno divergem, o comando falha em silêncio. O time de produto precisa alinhar o nome acessível ao texto exibido, sem exigir correspondência literal palavra por palavra em todos os casos.

Camada assistida por IA

Por que priorizar
Usuários que controlam o site por voz não conseguem ativar os controles porque falam o que veem na tela, mas o sistema espera palavras diferentes. O comando falha silenciosamente, bloqueando o acesso a notícias e conteúdos principais. Como afeta um público específico e impede navegação essencial, a correção deve ser planejada na próxima entrega.
Quem é afetado
Imagine tentar chamar um táxi pelo nome que vê na placa, mas o motorista só responde a um apelido diferente que ninguém consegue ler. Usuários que falam com o site para navegar enfrentam exatamente isso: veem um título na tela, falam o que leem, mas o site não reconhece o comando porque internamente usa outro nome. O resultado é que o controle não funciona.
O que precisa mudar
O texto visível dos links de notícia precisa estar alinhado com o nome que o sistema reconhece quando o usuário fala. O nome acessível deve começar com as mesmas palavras que aparecem na tela, para que quem usa comando de voz consiga ativar o controle falando exatamente o que vê.
Ação da gestão
Encaminhar para o time de produto e solicitar alinhamento entre o texto visível e o nome acessível dos links de notícia.

Descrição
Foram identificados 8 elementos onde o rótulo visível difere do nome acessível, violando o critério WCAG 2.5.3 Label in Name. Usuários que utilizam controle por voz são afetados, pois não conseguem ativar os controles ao pronunciar o texto visível. Esta inconsistência impede a navegação e interação eficaz para pessoas com deficiência motora que dependem de comandos de voz.
Critério de pronto
Alinhar o nome acessível com o rótulo visível em todos os 8 elementos identificados Validar a correção com ferramenta de teste de acessibilidade (axe, WAVE ou similar) Confirmar funcionamento com software de controle por voz (Dragon NaturallySpeaking ou similar)

A3 · Checklist Manual Recomendado (10)

Itens do relatório Lighthouse para revisão manual. Quando o texto coincide com padrões frequentes em inglês, é exibida uma versão em português; caso contrário mantém-se o original para cruzamento com a ferramenta.

  • Custom controls have associated labels Foram identificados elementos cujo rótulo visível diverge do nome acessível. Localização técnica específica removida para preservar a anonimização.
  • Custom controls have ARIA roles Controles interativos personalizados devem ter role ARIA adequado (ex.: role="button", role="checkbox") para que tecnologias assistivas compreendam sua função.
  • User focus is not accidentally trapped in a region Verifique manualmente: o usuário deve conseguir entrar e sair de qualquer controle ou região com Tab/Shift+Tab sem que o foco fique preso.
  • Interactive controls are keyboard focusable Controles interativos personalizados devem ser acessíveis por teclado (Tab para focar, Enter/Espaço para ativar) e exibir indicador de foco visível.
  • Interactive elements indicate their purpose and state Elementos interativos devem indicar claramente seu estado (ativo, desativado, expandido, selecionado) e ser distinguíveis de elementos estáticos visualmente e via ARIA.
  • The page has a logical tab order A ordem de foco pelo teclado (Tab) deve seguir a ordem visual da página. Verifique pressionando Tab em todos os elementos interativos: o foco deve percorrer o conteúdo de forma previsível.
  • The user's focus is directed to new content added to the page If new content, such as a dialog, is added to the page, the user's focus is directed to it. [Learn how to direct focus to new content]([URL omitida]).
  • Offscreen content is hidden from assistive technology Conteúdo fora da viewport deve estar oculto para tecnologias assistivas via display:none ou aria-hidden="true". Caso contrário, é lido pelo leitor de tela mesmo invisível.
  • HTML5 landmark elements are used to improve navigation Foi identificada a ausência de uma região semântica principal. A tag e a localização específicas foram omitidas para preservar a anonimização.
  • Visual order on the page follows DOM order A ordem visual deve corresponder à ordem do DOM. Se CSS reordena visualmente elementos, verifique se a sequência de leitura do leitor de tela ainda faz sentido.
