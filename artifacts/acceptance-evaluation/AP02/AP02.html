Camada determinística executiva

Impacto

Esta barreira impede a identificação correta do controle. Quem depende de leitor de tela ou navegação assistida não consegue entender com clareza o que o elemento faz, o que impede ou compromete a execução da tarefa.

Usuários cegos utilizam leitores de tela como NVDA, JAWS ou VoiceOver. Quando um elemento não tem nome ou descrição, ele simplesmente não existe para esse usuário: o software passa direto sem anunciar nada.

Como corrigir
Há links na página sem nenhum texto. O leitor de tela ou anuncia a URL crua ou pula sem dizer nada: em ambos os casos, impossível saber para onde o link vai. O time de produto precisa colocar um texto descritivo em cada um, indicando claramente o destino.

Camada assistida por IA

Por que priorizar
Usuários cegos que dependem de leitores de tela não conseguem identificar para onde os links levam, pois não há texto descritivo associado a eles. Isso cria uma barreira completa de navegação e compreensão do site, tornando a correção urgente.
Quem é afetado
Imagine tentar clicar em botões de um controle remoto sem saber o que cada um faz. Um usuário cego enfrenta exatamente isso ao encontrar links vazios: o leitor de tela não consegue dizer para onde vai, deixando-o sem saber se deve clicar ou não.
O que precisa mudar
Cada link precisa ter um texto claro e descritivo que indique seu destino ou função. Esse texto deve ser visível ou acessível ao leitor de tela, para que qualquer usuário saiba exatamente aonde será levado ao clicar.
Ação da gestão
Encaminhar para o time web como prioridade alta e solicitar revisão de todos os links sem texto descritivo.

Camada determinística executiva

Impacto

Esta barreira remove informação da experiência de quem usa leitura assistida. Quando a página depende de imagem para comunicar conteúdo ou ação, o usuário deixa de receber parte da informação necessária para entender ou concluir a tarefa.

Usuários cegos utilizam leitores de tela como NVDA, JAWS ou VoiceOver. Quando um elemento não tem nome ou descrição, ele simplesmente não existe para esse usuário: o software passa direto sem anunciar nada.

Como corrigir
Há links representados apenas por imagem sem texto alternativo que indique o destino. Para quem usa leitor de tela, ouvir "imagem, link" sem descrição é o mesmo que uma placa sem texto. O time de conteúdo e desenvolvimento precisa garantir que cada imagem-link tenha um texto alternativo que explique a ação ou o destino: não apenas o que a imagem mostra visualmente.

Camada assistida por IA

Por que priorizar
Usuários cegos que dependem de leitores de tela não conseguem identificar para onde os links levam quando eles são representados apenas por imagens sem descrição. Isso cria uma barreira completa de acesso a conteúdos e funcionalidades, tornando a correção urgente.
Quem é afetado
Imagine tentar navegar em um site onde vários botões e links são apenas imagens sem nenhum texto explicativo. Para quem usa leitor de tela, é como ouvir repetidamente 'imagem, link' sem saber o que cada um faz ou para onde leva. A pessoa fica perdida e não consegue acessar o conteúdo que está ali.
O que precisa mudar
Cada imagem usada como link precisa ter um texto descritivo que explique claramente a ação ou o destino do link. Esse texto deve ser lido em voz alta por leitores de tela, permitindo que qualquer usuário entenda para onde está clicando, independentemente de conseguir ver a imagem.
Ação da gestão
Encaminhar para o time de conteúdo e solicitar revisão de todas as imagens usadas como links no portal.

Camada determinística executiva

Impacto

Esta barreira não necessariamente impede a tarefa, mas torna a navegação menos previsível e mais cansativa. A pessoa até pode continuar, porém com mais esforço, mais tentativa e maior risco de se perder no conteúdo.

Usuários que saltam de título em título com leitor de tela precisam de uma sequência lógica (do geral ao específico). Níveis saltados ou ausência de h1 desorientam e tornam a página mais difícil de explorar.

Como corrigir
A hierarquia de títulos da página está fora de ordem: há títulos de nível 4 ou 5 sem que antes exista um nível 1 ou 2. Para quem navega pelo índice de títulos com leitor de tela, a estrutura da página fica incoerente. O time web precisa reorganizar os títulos em sequência lógica, do mais geral para o mais específico.

Camada assistida por IA

Por que priorizar
Usuários que navegam pelo índice de títulos com leitores de tela encontram uma estrutura incoerente, pois a hierarquia de títulos está fora de ordem. Isso prejudica a compreensão da organização da página e torna a navegação mais lenta e confusa para quem depende dessa funcionalidade.
Quem é afetado
Imagine tentar entender a organização de um documento quando os capítulos não seguem uma sequência lógica: você vê o capítulo 3, depois o capítulo 1, depois o capítulo 5. Usuários que usam leitores de tela enfrentam exatamente isso quando os títulos da página não estão em ordem, dificultando a localização de conteúdo e a compreensão da estrutura geral.
O que precisa mudar
Os títulos da página precisam ser reorganizados em sequência lógica, começando pelos títulos mais gerais e descendo para os mais específicos. Isso garante que qualquer pessoa, independentemente de como acessa a página, consiga entender a estrutura e navegar de forma coerente.
Ação da gestão
Incluir no planejamento e solicitar ao time web a reorganização dos títulos das páginas.

Camada determinística executiva

Impacto

Esta barreira reduz a clareza da interface e aumenta a chance de erro durante a navegação. O usuário encontra o controle, mas não recebe informação suficiente para agir com confiança.

Usuários que acionam interfaces por voz dependem de nomes visíveis e acessíveis coerentes, para que o comando falado corresponda ao elemento exibido na tela.

Como corrigir
O nome acessível deve conter o texto visível do link, preferencialmente no início, para que usuários de controle por voz consigam acionar o elemento pelo texto que enxergam na tela. Quando o rótulo visível e o nome interno divergem, o comando falha em silêncio. O time de produto precisa alinhar o nome acessível ao texto exibido, sem exigir correspondência literal palavra por palavra em todos os casos.

Camada assistida por IA

Por que priorizar
Usuários que controlam o site por voz não conseguem ativar este controle porque o comando que falam não corresponde ao que o sistema reconhece internamente. A barreira é de severidade média porque afeta diretamente a capacidade de navegação de um grupo específico, exigindo planejamento de correção na próxima entrega.
Quem é afetado
Imagine tentar chamar um táxi dizendo o endereço que vê na placa, mas o motorista só responde a um código diferente que está escrito em algum lugar invisível. Usuários que usam comando de voz falam o que veem na tela, mas o sistema espera outra palavra e o comando falha silenciosamente, deixando-os sem conseguir usar o controle.
O que precisa mudar
O texto visível do controle e o nome que o sistema reconhece para comando de voz precisam estar alinhados. O nome acessível deve conter o texto que aparece na tela, preferencialmente no início, para que quem usa voz consiga ativar o controle falando o que vê.
Ação da gestão
Encaminhar para o time de produto e solicitar alinhamento entre o texto visível e o nome acessível do controle.

A2 · Alertas para Revisão Manual (8)

A hierarquia de cabeçalhos deve ser sequencial sem pular níveis (h1 → h2 → h3…). Leitores de tela usam essa estrutura para navegação rápida pela página.
Event handler em elemento não interativo Alerta
Eventos dependentes de dispositivo (somente mouse) excluem usuários de teclado ou toque. Substitua por eventos universais: onclick em vez de onmouseover, ou adicione equivalentes de teclado.

Vários links consecutivos com o mesmo destino geram ruído para usuários de leitores de tela. Considere consolidar em uma única referência.

A3 · Checklist Manual Recomendado (10)

Itens do relatório Lighthouse para revisão manual. Quando o texto coincide com padrões frequentes em inglês, é exibida uma versão em português; caso contrário mantém-se o original para cruzamento com a ferramenta.

  • Custom controls have associated labels Foram identificados elementos cujo rótulo visível diverge do nome acessível. Localização técnica específica removida para preservar a anonimização.
  • Custom controls have ARIA roles Controles interativos personalizados devem ter role ARIA adequado (ex.: role="button", role="checkbox") para que tecnologias assistivas compreendam sua função.
  • User focus is not accidentally trapped in a region Verifique manualmente: o usuário deve conseguir entrar e sair de qualquer controle ou região com Tab/Shift+Tab sem que o foco fique preso.
  • Interactive controls are keyboard focusable Controles interativos personalizados devem ser acessíveis por teclado (Tab para focar, Enter/Espaço para ativar) e exibir indicador de foco visível.
  • Interactive elements indicate their purpose and state Elementos interativos devem indicar claramente seu estado (ativo, desativado, expandido, selecionado) e ser distinguíveis de elementos estáticos visualmente e via ARIA.
  • The page has a logical tab order A ordem de foco pelo teclado (Tab) deve seguir a ordem visual da página. Verifique pressionando Tab em todos os elementos interativos: o foco deve percorrer o conteúdo de forma previsível.
  • The user's focus is directed to new content added to the page If new content, such as a dialog, is added to the page, the user's focus is directed to it. [Learn how to direct focus to new content]([URL omitida]).
  • Offscreen content is hidden from assistive technology Conteúdo fora da viewport deve estar oculto para tecnologias assistivas via display:none ou aria-hidden="true". Caso contrário, é lido pelo leitor de tela mesmo invisível.

  • Visual order on the page follows DOM order A ordem visual deve corresponder à ordem do DOM. Se CSS reordena visualmente elementos, verifique se a sequência de leitura do leitor de tela ainda faz sentido.
