Resumo Executivo

Portal com barreiras de alta prioridade: ação imediata necessária

Esta auditoria automatizada identificou 3 barreiras de acessibilidade neste portal: sendo 1 barreira de alta prioridade, 2 barreiras de média prioridade.

As barreiras de alta prioridade afetam usuários de leitor de tela (cegos), usuários com mobilidade reduzida, além de quem depende de tecnologia assistiva quando o fluxo envolve os mesmos componentes.

1 problema pode ser corrigido em menos de 1 dia pela equipe técnica, com impacto imediato na qualidade da experiência.

Segundo o Censo Demográfico 2022, 14,4 milhões de brasileiros tinham algum tipo de deficiência, o que correspondia a 7,3% da população de 2 anos ou mais: muitas dessas pessoas ficam excluídas na prática quando o site tem barreiras de acesso.

Camada determinística executiva

Impacto

Esta barreira bloqueia a identificação correta do controle. Quem depende de leitor de tela ou navegação assistida não consegue entender com clareza o que o elemento faz, o que impede ou compromete a execução da tarefa.

Leitores de tela

Como corrigir
Campos do formulário estão sem etiqueta. Quem usa leitor de tela chega ao campo e ouve apenas "campo de texto": sem saber o que deve preencher. O time de produto precisa vincular um rótulo a cada campo para que o nome do campo seja anunciado quando o foco chegar nele.

Camada assistida por IA

Por que priorizar
Usuários que dependem de leitores de tela não conseguem identificar o propósito de campos de formulário quando chegam a eles, pois ouvem apenas a indicação genérica de tipo de campo sem saber o que devem preencher. Essa barreira impede o acesso completo ao formulário e deve ser corrigida com urgência.
Quem é afetado
Imagine tentar preencher um formulário em um ambiente escuro onde as etiquetas dos campos não são visíveis. Quem usa leitor de tela enfrenta situação semelhante: chega ao campo e ouve apenas 'campo de texto', sem saber se deve informar nome, email, telefone ou outra informação. Sem essa orientação, fica impossível completar o formulário corretamente.
O que precisa mudar
Cada campo do formulário precisa ter um rótulo vinculado a ele, de modo que quando o usuário chegar ao campo, o nome dele seja anunciado automaticamente. Isso permite que qualquer pessoa saiba exatamente o que deve preencher em cada espaço.
Ação da gestão
Encaminhar para o time web e solicitar revisão de todos os campos de formulário e seus rótulos.

Camada assistida por IA

Por que priorizar
Usuários que navegam apenas por teclado enfrentam uma ordem de foco desordenada, o que prejudica a experiência de acesso rápido ao conteúdo principal. Como a barreira afeta elementos de navegação essencial, a correção deve ser planejada na próxima entrega.
Quem é afetado
Quem usa teclado para navegar em um site espera que a tecla Tab o leve pelos elementos na ordem lógica da página. Quando essa ordem fica confusa, é como tentar encontrar um caminho em um prédio onde as placas de direção apontam para lugares errados.
O que precisa mudar
Os links de pular para seções principais precisam ser ajustados para que a navegação por teclado siga a ordem natural da página. Isso garante que qualquer pessoa consiga chegar rapidamente ao conteúdo que procura sem se perder na sequência de elementos.
Ação da gestão
Encaminhar para o time web e solicitar revisão da ordem de navegação dos links de pular para conteúdo.

Camada determinística executiva

Impacto

Prejudica a experiência sem necessariamente bloquear o acesso. Vale incluir na próxima rodada de melhorias.

Usuários com limitação motora dependem de alvos clicáveis adequados, espaçamento entre controles e navegação previsível para evitar toques acidentais e retrabalho.

Como corrigir
Vários botões e links do site têm área de clique menor do que o mínimo para uso em celular. Quem tem tremor ou dedo largo acaba ativando o elemento errado. O time de produto precisa aumentar essas áreas: não é mudança visual grande, mas faz diferença real para quem usa o site em mobilidade ou com dificuldade motora.

Camada assistida por IA

Por que priorizar
Usuários com limitações motoras não conseguem ativar os botões de chat porque as áreas de toque são muito pequenas ou estão muito próximas uma da outra. Essa barreira impede o acesso a uma funcionalidade importante do site e deve ser corrigida no próximo ciclo de desenvolvimento.
Quem é afetado
Imagine tentar apertar um botão muito pequeno em um painel de controle enquanto usa luvas ou tem tremor nas mãos. Usuários com limitações motoras enfrentam essa dificuldade todos os dias ao interagir com elementos muito compactos na tela. Os botões de chat do site estão tão pequenos ou tão próximos que fica quase impossível tocá-los com precisão.
O que precisa mudar
Os botões de chat precisam ter uma área de toque maior e estar mais afastados um do outro, para que qualquer pessoa consiga ativá-los com facilidade, mesmo com pouca precisão motora. Revise o tamanho e o espaçamento dos elementos indicados até atingir o padrão mínimo de acessibilidade.
Ação da gestão
Encaminhar para o time de produto e solicitar aumento das áreas de toque e clique dos botões de chat.

A3 · Checklist Manual Recomendado (10)

Itens do relatório Lighthouse para revisão manual. Quando o texto coincide com padrões frequentes em inglês, é exibida uma versão em português; caso contrário mantém-se o original para cruzamento com a ferramenta.

  • Custom controls have associated labels Controles interativos personalizados devem ter rótulos associados via aria-label ou aria-labelledby para que leitores de tela anunciem seu propósito.
  • Custom controls have ARIA roles Controles interativos personalizados devem ter role ARIA adequado (ex.: role="button", role="checkbox") para que tecnologias assistivas compreendam sua função.
  • User focus is not accidentally trapped in a region Verifique manualmente: o usuário deve conseguir entrar e sair de qualquer controle ou região com Tab/Shift+Tab sem que o foco fique preso.
  • Interactive controls are keyboard focusable Controles interativos personalizados devem ser acessíveis por teclado (Tab para focar, Enter/Espaço para ativar) e exibir indicador de foco visível.
  • Interactive elements indicate their purpose and state Elementos interativos devem indicar claramente seu estado (ativo, desativado, expandido, selecionado) e ser distinguíveis de elementos estáticos visualmente e via ARIA.
  • The page has a logical tab order A ordem de foco pelo teclado (Tab) deve seguir a ordem visual da página. Verifique pressionando Tab em todos os elementos interativos: o foco deve percorrer o conteúdo de forma previsível.
  • The user's focus is directed to new content added to the page Quando conteúdo novo é adicionado à página (diálogo, notificação, painel), o foco deve ser direcionado automaticamente para ele e retornar ao elemento de origem ao ser fechado.
  • Offscreen content is hidden from assistive technology Conteúdo fora da viewport deve estar oculto para tecnologias assistivas via display:none ou aria-hidden="true". Caso contrário, é lido pelo leitor de tela mesmo invisível.
  • HTML5 landmark elements are used to improve navigation Use elementos HTML5 de marco semântico (<main>, <nav>, <header>, <footer>, <aside>) para melhorar a navegação por tecnologias assistivas.
  • Visual order on the page follows DOM order A ordem visual deve corresponder à ordem do DOM. Se CSS reordena visualmente elementos, verifique se a sequência de leitura do leitor de tela ainda faz sentido.
